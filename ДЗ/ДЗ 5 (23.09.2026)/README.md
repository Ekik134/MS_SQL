## Что изучалось
На занятии были рассмотрены практические аспекты работы с DML- и DDL-триггерами в MS SQL Server: создание триггеров на события вставки, удаления и изменения данных (`AFTER INSERT`, `AFTER DELETE`, `INSTEAD OF INSERT`), использование виртуальных таблиц `inserted` и `deleted`, а также создание DDL-триггеров для отслеживания и запрета изменений структуры базы данных (например, удаления представлений).

## Суть задания
Выполнить практические задания по работе с триггерами в T-SQL:

### DML-триггеры
1. **AFTER INSERT** — создать триггер, срабатывающий после вставки данных; вывести вставленные значения через таблицу `inserted`, чтобы убедиться в корректности операции.

2. **AFTER DELETE** — создать триггер, срабатывающий после удаления; вывести сообщение об успешном удалении.

3. **INSTEAD OF INSERT** — создать триггер, который вместо простой вставки выполняет дополнительные действия: выводит данные до изменения, выполняет изменение, выводит данные после. Использовать таблицы `inserted` (копия вставляемых строк) и `deleted` (копия строк до изменения).

### DDL-триггеры
1. **Запрет на удаление представлений** — создать DDL-триггер на событие `DROP_VIEW`, который откатывает операцию через `ROLLBACK` (поскольку конструкция `INSTEAD OF` в DDL-триггерах не работает).

2. **Сообщение об изменении таблицы** — создать DDL-триггер на событие `ALTER_TABLE`, который выводит информационное сообщение при изменении структуры таблицы.
