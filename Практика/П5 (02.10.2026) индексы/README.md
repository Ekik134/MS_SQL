## Что изучалось
На занятии были рассмотрены практические аспекты работы с индексами в MS SQL Server: создание кластеризованных индексов на heap-таблицах, некластеризованные индексы для точечного поиска, разница между операторами Seek и Scan, влияние селективности (selectivity) на выбор индекса оптимизатором, покрывающие индексы через INCLUDE, правило левого префикса в составных индексах, принцип SARGable, а также сравнение кластеризованного индекса и heap для диапазонных запросов.

## Суть задания
Выполнить практические задания по работе с индексами в T-SQL:

1. **Создание кластеризованного индекса на heap-таблице** — преобразовать heap в кластеризованную таблицу, проверить изменение плана выполнения и снижение logical reads.

2. **Некластеризованный индекс для точечного поиска** — создать некластеризованный индекс и убедиться, что SQL Server использует Index Seek вместо Table Scan.

3. **Разница между Seek и Scan** — сравнить поведение оптимизатора на трёх запросах: точечный поиск (Seek), поиск по узкому диапазону (Range Seek), выборка большой части таблицы (Scan — последовательное чтение дешевле).

4. **Влияние selectivity на выбор индекса** — показать, что при низкой селективности (выборка 50% строк) SQL Server игнорирует индекс и делает Scan; при высокой селективности (уникальный Email) — выполняет Seek, а при SELECT добавляет Key Lookup за недостающими столбцами.

5. **Удаление и пересоздание индекса** — продемонстрировать, что после DROP и CREATE INDEX план выполнения и статистика остаются идентичными.

6. **Covering index через INCLUDE** — создать индекс без INCLUDE (появляется Key Lookup) и с INCLUDE (Key Lookup устраняется, индекс становится покрывающим).

7. **Порядок столбцов в составном индексе** — создать два индекса с разным порядком столбцов (IX_1: RegionID, SaleDate; IX_2: SaleDate, RegionID), сравнить их эффективность для разных запросов и объяснить правило левого префикса и принцип SARGable.

8. **Кластеризованный индекс vs. heap для диапазонных запросов** — сравнить logical reads и время выполнения на двух таблицах по 300 000 строк: heap выполняет Table Scan, кластерный индекс — Clustered Index Seek (Range), что даёт снижение I/O в десятки раз.
