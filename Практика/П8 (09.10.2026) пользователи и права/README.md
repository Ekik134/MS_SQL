## Что изучалось
На занятии были рассмотрены практические аспекты администрирования безопасности в MS SQL Server: создание SQL-логинов и пользователей базы данных (в том числе без логина), назначение фиксированных и пользовательских серверных ролей и ролей БД, выдача точечных прав через GRANT/DENY/REVOKE на уровне объектов и хранимых процедур, просмотр эффективных прав, а также настройка серверного аудита (запись в файл, отслеживание входов, изменений разрешений и членства в ролях).

## Суть задания
Выполнить практические задания по управлению доступом и аудиту в MS SQL Server:

1. **Создание SQL-логина с политикой паролей** — создать логин средствами SSMS, проверить его права в `master` (роль `public` даёт только чтение), столкнуться с ограничением «только Windows-аутентификация» и создать новый сервер с SQL-аутентификацией.

2. **Создание пользователя без логина** — продемонстрировать изоляцию прав: пользователь без логина не может войти, но используется как контейнер для разрешений (например, для impersonation через `EXECUTE AS`).

3. **Создание логина с истёкшим сроком действия пароля** — создать логин с `CHECK_EXPIRATION = ON` и `CHECK_POLICY = OFF`; вход при этом всё равно проходит (поведение зависит от версии SQL Server и настроек политики).

4. **Просмотр списка всех логинов и пользователей** — использовать `sys.server_principals` и `sys.database_principals`.

5. **Добавление логина в фиксированную серверную роль** — добавить логин в `securityadmin`, проверить членство через `sys.server_role_members`; роль даёт управление логинами, сброс паролей, выдачу прав.

6. **Создание пользовательской серверной роли** — создать роль, выдать ей право (`GRANT ALTER ANY LOGIN`), добавить логин, войти под ним и создать новый логин.

7. **Проверка членства в серверных ролях** — запросить `sys.server_role_members` для аудита текущих назначений.

8. **Удаление логина из роли и удаление пользовательской роли** — продемонстрировать, что нельзя удалить роль, пока в ней есть члены: сначала `DROP MEMBER`, затем `DROP ROLE`.

9. **Добавление пользователя в фиксированную роль БД** — создать логин, пользователя в БД, добавить в `db_datareader`, проверить, что чтение работает, а изменение/добавление — нет.

10. **Создание пользовательской роли с точечными правами** — создать роль, выдать `SELECT`/`INSERT` только на конкретную таблицу, добавить пользователя, проверить права.

11. **Запрет (DENY) на уровне объекта** — выдать `GRANT SELECT` на схему, затем `DENY SELECT` на конкретную таблицу; убедиться, что DENY имеет приоритет.

12. **Права на выполнение хранимых процедур** — выдать `GRANT EXECUTE` на одну процедуру, проверить, что она выполняется, а другая (без прав) — нет.

13. **Просмотр эффективных прав пользователя** — использовать `sys.database_permissions` и `sys.database_principals` для аудита прав.

14. **Создание серверного аудита с записью в файл** — создать аудит `SecurityAudit` с параметрами: путь `C:\AuditLogs\`, `MAXSIZE = 100 MB`, `MAX_ROLLOVER_FILES = 5`, `QUEUE_DELAY = 1000`, `ON_FAILURE = CONTINUE`, активировать.

15. **Аудит успешных и неудачных входов** — создать спецификацию `LoginAuditSpec` с группами `SUCCESSFUL_LOGIN_GROUP` и `FAILED_LOGIN_GROUP`, проверить запись неудачного входа через `sys.fn_get_audit_file`.

16. **Аудит изменений разрешений на уровне сервера** — добавить `SERVER_PERMISSION_CHANGE_GROUP` в спецификацию, выполнить `GRANT ALTER ANY LOGIN TO TestUser01`, проверить запись в аудит-логе.

17. **Аудит изменений членства в ролях базы данных** — добавить `DATABASE_ROLE_MEMBER_CHANGE_GROUP`, выполнить `ALTER ROLE db_datareader ADD/DROP MEMBER`, проверить фиксацию обоих событий.
