## Что изучалось
На занятии были рассмотрены основы работы с транзакциями в MS SQL Server: управление транзакциями (`BEGIN TRANSACTION`, `COMMIT`, `ROLLBACK`), использование точек сохранения (`SAVE TRANSACTION`), подсчёт уровня вложенности через `@@TRANCOUNT`, анализ блокировок через `sys.dm_tran_locks`, моделирование взаимоблокировок (deadlock), а также уровни изоляции `READ UNCOMMITTED` и `READ COMMITTED` и связанные с ними аномалии чтения («грязное чтение» и «неповторяющееся чтение»).

## Суть задания
Выполнить практические задания по работе с транзакциями в T-SQL:

1. **Простая транзакция** — объявить `BEGIN TRANSACTION`, вставить данные, проверить изменение количества строк, подтвердить изменения через `COMMIT`, убедиться, что данные сохранились.

2. **Транзакция с откатом** — выполнить аналогичную вставку, но вместо `COMMIT` использовать `ROLLBACK`, продемонстрировав откат всех изменений к моменту начала транзакции.

3. **Транзакции с точками сохранения** — выполнить три вставки, расставить `SAVE TRANSACTION A` и `SAVE TRANSACTION B` между ними, затем откатиться к точке B (отменяется только последняя вставка), затем к точке A (отменяются все, кроме первой), и подтвердить транзакцию — в результате остаётся только первая вставка.

4. **Подсчёт количества транзакций** — продемонстрировать работу `@@TRANCOUNT`: 0 — транзакция не открыта, 1 — открыта, 2 и более — вложенные транзакции.

5. **Просмотр блокировок** — изучить представление `sys.dm_tran_locks`: тип ресурса (`resource_type`), имя БД (`DB_NAME(resource_database_id)`), ID сессии (`request_session_id`), режим блокировки (`request_mode` — S = разделяемая, X = эксклюзивная), статус (`request_status` — GRANT).

6. **Deadlock (взаимоблокировка)** — смоделировать ситуацию: две сессии блокируют разные строки и пытаются изменить строки друг друга; возникает бесконечное ожидание, пока SQL Server не выберет «жертву» и не разорвёт конфликт. В данном случае сервер справился сам без ошибки.

7. **Параллельные транзакции с READ UNCOMMITTED** — продемонстрировать «грязное чтение»: одна транзакция читает данные, вторая в этот момент их меняет без подтверждения, первая видит незафиксированные изменения.

8. **READ COMMITTED и неповторяющееся чтение** — продемонстрировать, что при этом уровне изоляции «грязное чтение» невозможно (читаются только зафиксированные данные), но возможно «неповторяющееся чтение»: между двумя чтениями вторая транзакция меняет данные, и результаты чтений различаются.
